# configs/

Public benchmark descriptors: the two dataset yaml files and the measured
degradation parameters. No method-specific configuration is included here.

| file | purpose |
|---|---|
| `wtvd.yaml` | Ultralytics dataset yaml for the leakage-free WTVD split. Paths are relative, so the folder can be moved anywhere; train 3577 / val 444 / test 177 |
| `extreme_wtvd.yaml` | one entry per degradation family (`fog`, `motion`, `low`, `composite`) plus `combined`, the 16 792-image pool |
| `degradation_params.json` | the parameter ranges actually drawn when the benchmark was built — the machine-readable form of the paper's conditions table |

Both yamls declare the same seven classes:

```
nc: 7
names: ['burning', 'crack', 'deformity', 'dirt', 'oil', 'peeling', 'rusty']
```

## Usage

Unzip the archives so that `datasets/WTVD/` and `datasets/Extreme-WTVD/` exist,
then point Ultralytics at the yaml:

```bash
yolo detect train data=configs/wtvd.yaml model=yolo11n.pt epochs=400 imgsz=640
yolo detect val   data=configs/extreme_wtvd.yaml model=runs/detect/train/weights/best.pt
```

`extreme_wtvd.yaml` uses family-prefixed keys (`combined.train`, `fog.test`, …)
rather than a flat `train:`/`val:` mapping, because the families are evaluated
separately as well as pooled. Select the pool in your training wrapper rather
than editing the file.

## Why these parameters are published

The three non-generative families are produced by physical operators parameterised
by continuous quantities, so the construction is reproducible from
`degradation_params.json` alone. The fog family is generated by HazeGen, whose
released weights are used unchanged; its only controls are the mixture
coefficient (0.85), the sampler step count (50) and the haze text prompt.
